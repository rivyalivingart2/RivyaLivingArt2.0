## Editorial workflow

The old-section checklist is available inside Homepage Studio. “Add missing detailed chapters” inserts only missing canonical chapters as hidden, unreviewed drafts. It preserves existing copy, order, product selections, images, crop values and revisions; it refuses the operation when it would exceed the 20-chapter limit. Repeated use is idempotent. Existing custom chapters are never deleted or overwritten.

Each restored chapter has heading, eyebrow, substantial paragraphs, optional checklist, editorial source note, layout, primary/secondary action and the existing published-image picker. Source notes are for staff and never enter public rendering. Enable and mark ready only after reviewing copy and references. Save captures published dependencies; exact preview, administrator publication, anonymous verification and restoring a saved revision use the P2/P3 workflow.

Three collections move nearer the first product selection in the reviewed QA composition. Text-only chapters stay intentionally text-led; an absent image does not leave an empty layout column. This is a composition choice, not an invitation to fill every chapter with the same image.

## Responsive and motion treatment

Desktop allows image/text, reversed image/text and editorial statements. Mobile returns to a single natural reading column and uses independent mobile crops. Long chapters grow with their content. The compact table of contents expands to three, two or one columns and links to semantic section headings. Native controls work by keyboard; journey cards keep named links and visible focus.

Motion is limited to 180 ms color/border feedback when reduced motion is not requested. There is no autoplay, scroll hijacking or essential content hidden behind animation. Approved still images are sufficient for P4A. Video remains optional and unselected; later use requires its separate footage, caption, playback and cost checks.

## Release boundary

QA reuses P3's reviewed Drive assets and recorded provenance. Application defaults contain no isolated asset UUIDs. A later authorized release must select the corresponding published images in the destination Studio, review the actual saved preview, then publish deliberately. Existing products, contact facts, scraper and gallery/media records are not migrated or edited.
