## Catalogue reuse boundaries

The discovered workbook contains Products, Pricing, Gallery, Settings, CATALOGUE ORDER, ACTIVE CATALOGUE, CATALOGUE AUTOMATION and START HERE. Product/pricing headers already distinguish stable IDs, display order, inclusion, bilingual content, image provenance, photo rights and price status. These are reusable design inputs; the existing catalogue's rows are not approved application imports.

The V2 source creates dated new Slides/PDF outputs, preserves earlier outputs, uses `LockService`, and performs image lookup from relative-path-derived file names. It stores queues, latest output references and run/error metadata in Apps Script DocumentProperties. The target requires canonical job and application metadata in Sheets and stable Drive IDs, so source reuse requires an explicit adaptation. A Rivya-named standalone Apps Script search returned no results; this does not exclude a container-bound project.
