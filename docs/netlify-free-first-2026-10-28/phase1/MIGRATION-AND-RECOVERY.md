## Record migration and conflict handling

Export from a repeatable-read, read-only source transaction. Pin source fingerprint, schema and migration identity. Preserve original keys, column types, nulls versus empty strings, decimal-string prices, integer paise where the domain uses them, timestamps, URLs, variants, source language text, disclosures and revision history. Use namespace plus original key for target identity and retain a private reversible crosswalk. Six absent mapped tables remain absent; do not manufacture zero-row imports as completed work.

Validate SQL constraints and JSON relationships. Plan batches within one canonical transaction boundary. Write large full documents first using immutable version identity and verified checksum; then atomically link their references with records, receipt/history and audit. A prewritten unlinked artifact is a tracked orphan, not a saved record. Unknown create/copy outcomes are quarantined and reconciled before retry; do not invent output IDs.

For each source row record privately: source key/hash, schema version, target key/revision/hash, operation identity, readback result and conflicts. Compare target payload hashes after resolving referenced documents, not merely the reference envelopes. Repeated runs must replay or report an exact conflict. Never use last-write-wins to replace populated valid content. Title corrections require a traceable decision. Map references inside JSON and verify every applicable foreign relationship.

## Future cutover, interruption and post-cutover recovery

Before production actions: prepare exact scope and authorization, verified checkpoint, durable write fence for every mutation route, drain/inflight inventory, final source delta and target readback. Short downtime is preferable to an invented universal 30-second budget. Measure the actual interval. Fences and authority epochs must survive process restarts; process memory cannot coordinate independent Netlify workers.

Switch one coherent configured authority epoch after all consumers support it. Old workers must reject writes under the retired epoch. Prevent source and target from both accepting the same record family's writes. Verify authenticated reload, public bundle, private media, intake, retry and denial paths on the exact deployment. Disabled indexing/intake/retry flags do not silently turn on.

If interrupted before switch, retain source authority and quarantine any uncertain target writes. After switch, fence new target writes, export and reconcile the post-cutover delta before any rollback. Restoring a stale SQL snapshot alone would lose new records and is forbidden. Rehearse interrupted writer, failed publication, expired lease and restore on isolated records before release. No provider may be deleted until replacement, reconciliation and recovery pass and the owner authorizes the exact destructive action. OLDWEBSITE remains a reference.
