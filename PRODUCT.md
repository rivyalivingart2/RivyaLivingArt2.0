## Protected experience and content

Preserve the approved homepage, Rivya / Creations, The Signature, footer, branding,
contact information, navigation, responsive behavior, selected images and current
Studio login. Restore the authenticated Studio's full design/workflows from the
OLDWEBSITE reference; keep that source available.

Preserve every valid existing product, identity, URL, price, variant, history,
original file and relationship. Add no products. Import no archived catalogue or
Sheets lists. Reuse the approved image set with truthful attribution and content
associations. Do not invent customers, reviews, sales or completed projects.

## Required behavior

- Netlify hosts the website, Studio, server functions and previews. Preserve
  www.rivyalivingart.com and working GoDaddy DNS/email.
- Prefer private Google Sheets and Drive. Give each record type one authoritative
  store; no uncontrolled dual writes or temporary memory presented as persistence.
- Any database exception must have demonstrated need, the smallest scope,
  verified ongoing-free ownership/limits, export/restore and safe exhaustion.
  No paid upgrade, expiring paid trial or automatic recharge.
- Preserve authentication, roles, secure cookies, identity/recovery and durable
  audit. Controlled writes require validation, expected revisions, idempotency,
  conflict handling and trustworthy recovery from uncertain outcomes.
- Studio workflows must save/reload durable data and handle roles, validation,
  drafts/publication, filters, pagination, history and errors.
- Jobs, research and catalogue generation survive interruption and separate
  workers. Research cannot create products. Catalogues require real editable
  Google Slides and verified downloadable PDFs.
- Forms report success only after persistence; public publication exposes approved
  fields coherently. Private media requires authorization.

## Acceptance and operations

Use real provider/browser evidence and protect the existing public experience.
Keep implementation, local tests, provider tests, migration, cutover, production
release and retirement statuses separate. The programme remains incomplete.

SQL/Blob and existing recovery resources stay available until the replacement,
reconciliation and recovery are verified. Exact destructive retirement needs
specific authorization. Keep secrets/private evidence out of GitHub/chat and
keep the Codex cloud environment unpublished.
